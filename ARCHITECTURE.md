# Архитектура Chunkwake (Minecraft 26.3)

## Приоритеты и целевые метрики
1. **Совместимость с Paper-плагинами — приоритет №1.** При конфликте «скорость vs совместимость» выигрывает совместимость: семантика событий, порядок, синхронность главного потока для обычных плагинов сохраняются как в Paper. Ускорение достигается там, где плагины этого не видят (движок, сеть, I/O, генерация, свет, pathfinding).
2. **Скорость:** TPS ≥ 20.0 всегда; MSPT low ≤ 0.001 мс, high ≤ 0.1 мс.

Честная оговорка: 0.001 мс (1 мкс) на тик достижимо только для пустого/простаивающего сервера (тик без работы). Поэтому цели фиксируем по профилям нагрузки в `docs/criteria.md`:
- **Idle (0 игроков, загружен спавн):** low ≤ 0.001 мс, high ≤ 0.1 мс — жёсткий CI-гейт.
- **Light (10–50 игроков, без плагинов):** цель high ≤ 0.1 мс на регион.
- **Heavy (500+ игроков, топ-плагины):** TPS 20.0, MSPT p99 сравнивается с Paper/Folia (цель — в разы ниже).
Плагинный код в JVM в бюджет движка не входит — его время меряем отдельно (timings per plugin), чтобы не маскировать регрессии ядра.

Следствия для архитектуры: никакой работы в тике «на всякий случай» (event-driven, ленивые тикеры, пропуск пустых регионов), JNI-события не вызываются, если на них нет слушателей, zero-alloc горячие пути, бенчмарки (criterion) в CI с порогами.

## Революционные идеи архитектуры (то, чего нет ни в одном ядре)

Главная проблема рынка: **Paper совместим, но однопоточен; Folia параллельна, но ломает плагины.** Наша ставка — убрать этот выбор. Семь столпов:

### 1. Спекулятивный параллелизм с Paper-семантикой (STM-тик)
Обычные (не-Folia) плагины видят мир «как будто один главный поток», но исполняются параллельно:
- Каждый регион тикается в своём потоке как **транзакция**: мост записывает read/write-set (какие чанки, сущности, инвентари, глобальные объекты трогал плагин).
- Коммит — в детерминированном порядке, совпадающем с порядком Paper (по регионам, затем по событиям). Если write-set двух транзакций пересёкся → откат проигравшей и **последовательное** переисполнение. Плагин никогда не увидит гонку.
- Статистика конфликтов per-plugin: «болтливые» плагины (глобальные Map, статические счётчики) автоматически переводятся в serial lane, остальные остаются параллельными.
- Результат: совместимость уровня Paper при масштабировании уровня Folia. Это ключевая «революция».

### 2. Динамические «острова» вместо фиксированных регионов
Folia режет мир на регионы фиксированной сетки и умирает, когда все игроки в одной точке. У нас:
- Граф взаимодействий (сущности, редстоун-сети, жидкости, хопперы) перестраивается каждый тик; связные компоненты = острова, независимые острова тикаются параллельно с work-stealing (rayon).
- Плотная точка делится дальше по фазам: внутри острова параллельны фазы без зависимостей (AI/pathfinding, коллизии, свет, рандомтики блоков) с барьерами.
- Простаивающие острова **не тикаются вообще** (event-driven: пробуждение по таймеру/событию) → idle-тик = проверка пустой очереди ≈ наносекунды. Отсюда реальные 0.001 мс.

### 3. Event-sourced мир (журнал изменений как первичный источник)
Каждое изменение блока/сущности — запись в лог изменений тика:
- **Сеть**: дельты для клиентов строятся из лога, пакеты кодируются один раз и рассылаются всем подписчикам (zero-copy `Bytes`).
- **Хранение**: WAL → сохранение без лагов и без потери данных при краше; чекпоинты в Anvil.
- **Встроенный rollback** (как CoreProtect, но бесплатно по CPU) и **детерминированный replay** — баг-репорт = файл лога, воспроизводимый бит-в-бит.
- Плагины получают этот лог через API (`chunkwake-api`), вместо тысяч мелких событий.

### 4. Мост к Java нового поколения: Panama FFM + общая память
- Вместо JNI — **Foreign Function & Memory API** (Java 22+): дешёвые downcall/upcall.
- Read-only данные (блоки чанков, позиции, здоровье, инвентари) отображаются в JVM как `MemorySegment` над off-heap памятью Rust → `getBlock()`/`getLocation()` вообще не пересекают границу языков.
- Событие не пересекает границу, если на него нет слушателей (bitmap подписок), и батчится, если слушатели есть.
- GC JVM никогда не останавливает движок: Rust-тик не ждёт JVM, кроме точек коммита транзакции.

### 5. Компилятор совместимости плагинов (load-time bytecode analysis)
При загрузке jar анализируется ASM-ом:
- Обнаружение NMS/CraftBukkit/reflection → автоматический ремап на наши shim-классы (популярные паттерны: ProtocolLib, NBT-API, packet-injection через Netty pipeline — эмулируем pipeline).
- Классификация потокобезопасности (статические изменяемые поля, `synchronized`, использование `Bukkit.getScheduler`) → начальная lane для STM.
- Отчёт совместимости `/compat <plugin>` для админа ещё до запуска.

### 6. Data-oriented движок
- ECS с SoA-хранением (архетипы), SIMD для палитр/света/коллизий, bitset-палитры секций.
- Арена-аллокаторы на тик: zero-alloc горячий путь, никакого GC в ядре.
- Предкодированные кэши чанк-пакетов, инвалидируемые по логу изменений.
- Сеть: IOCP (Windows) / io_uring (Linux), декодирование пакетов параллельно тику в отдельном конвейере (pipelining: тик N симулируется, пока тик N−1 сериализуется и отправляется).

### 7. Наблюдаемость встроена в архитектуру
- Каждый остров/транзакция/плагин — свой счётчик времени; встроенный профайлер (уровня spark) без агентов.
- Метрика «стоимость плагина в мс и в конфликтах» — админ видит, кто тормозит сервер.

### Что сознательно НЕ делаем
- Не меняем ванильные механики ради скорости по умолчанию (LOD-симуляция далёких зон — только опция).
- Не требуем от плагинов переписывания: Folia-API — ускоритель, а не обязаловка.

### Новые этапы под революционные части
- **M4a** — FFM-мост + off-heap views (вместо простого JNI MVP).
- **M4b** — STM-тик: read/write-set, детерминированный коммит, откат; тест-сьют гонок на синтетических плагинах.
- **M6a** — компилятор совместимости (ASM-анализ + shim'ы).
- **M3a** — event-sourced лог изменений + WAL (закладывается одновременно с миром, т.к. на нём строятся сеть и хранение).

## Архитектура (верхний уровень)
Cargo workspace:
- `crates/protocol` — пакеты 26.3 (codegen из данных ванилы: `java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar --all`), VarInt, NBT, текстовые компоненты, сжатие, шифрование.
- `crates/net` — tokio, состояния handshake/status/login/configuration/play, лимиты, Velocity/BungeeCord forwarding.
- `crates/registry` — блоки, предметы, биомы, data-driven реестры, теги, датапаки.
- `crates/world` — чанки/секции/палитры, Anvil (.mca) чтение/запись, light engine, генерация (сначала flat/void, затем ванильный генератор).
- `crates/region` — регионы-планировщик: мир делится на независимые регионы, каждый тикается в своём потоке (rayon/свой пул), слияние/разделение регионов, передача сущностей между ними. Глобальный тик для общих вещей (время, погода, команды консоли).
- `crates/entity` — ECS (bevy_ecs или собственный), AI, физика, коллизии.
- `crates/gameplay` — механики ванилы (блоки, редстоун, инвентари, крафт, бой, мобы) — самая длинная часть.
- `crates/jvm-bridge` — запуск JVM через `jni` crate, загрузка плагинов, маршалинг событий/вызовов, handle-объекты на Rust-сущности.
- `java/api-impl` — Gradle-модуль: реализация `org.bukkit.*`/Paper/Purpur API (используем официальные paper-api/purpur-api как compile-only, реализуем `CraftServer`-подобный слой поверх native-методов). Опционально — паблишим `chunkwake-api` с расширениями.
- `crates/server` — бинарник, конфиги (`server.properties`, `bukkit.yml`, `paper-*.yml`, `purpur.yml` — читаем привычные), консоль, метрики.

Модель потоков для плагинов: как Folia — `RegionScheduler`, `EntityScheduler`, `GlobalRegionScheduler`, `AsyncScheduler`. Плагины, не помеченные `folia-supported: true`, запускаются в **режиме совместимости** (выполнение их задач/событий сериализуется через глобальный lock-тик) — это главное отличие от Folia, которая такие плагины просто не грузит. Режим совместимости — **по умолчанию**; параллельная модель включается только для плагинов, явно её заявивших.
