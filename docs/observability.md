# Наблюдаемость

Сервер умеет показывать актуальную нагрузку без интерактивных панелей и без
внешних агентов: снимок снимается раз в секунду и отдаётся тремя способами.

| Способ | Когда нужен |
|---|---|
| `/top` в игре | посмотреть нагрузку из чата, не переключаясь в терминал |
| `chunkwake top` | разовый снимок или `--watch` в соседнем окне |
| `GET /` в браузере | живой дашборд: графики за 15 минут, ядра, мир, сеть |
| `GET /metrics` | Prometheus и Grafana |
| `GET /snapshot` | `chunkwake top` и лаборатория (JSON) |
| `GET /api/events` | поток SSE, которым живёт дашборд |
| `GET /api/profile` | профиль тика по подсистемам (JSON) |

## Дашборд в браузере

`http://127.0.0.1:25585/` — та же нагрузка, что в `chunkwake top`, но с
графиками и без установки чего-либо: страница вшита в бинарник, внешних
библиотек и CDN нет, работает без интернета.

Что на странице:

- **KPI** — TPS (now/1м/5м/15м), MSPT (last/p95/p99 и бюджет), загрузка
  машины и процесса, RSS, игроки, чанки в симуляции.
- **Графики** за последние 15 минут: TPS с линией цели, MSPT с p95 и бюджетом,
  загрузка CPU (машина и сервер), RSS процесса, скорость сети в обе стороны,
  игроки онлайн.
- **Ядра** — полоска на каждое ядро, цвет по загрузке (зелёный до 70 %,
  жёлтый до 90 %, красный выше).
- **Тик, мир, сеть** — те же строки, что в ANSI-таблице `chunkwake top`.

Данные идут потоком `GET /api/events` (Server-Sent Events): сервер сам присылает
кадр после каждой публикации снимка, страница ничего не опрашивает. Если поток
оборвался, браузер переподключается сам, а страница подстраховывается
запросом `/api/snapshot`. История на сервере — 900 точек по секунде; она
доступна и отдельно как `GET /api/history`, поэтому графики не теряются при
перезагрузке страницы.

Дашборд слушает тот же адрес, что и метрики (`metrics-bind`), и по умолчанию
это только loopback: наружу страница и цифры не уходят.

## Доступ к дашборду

На loopback настройка не нужна: `chunkwake top` и браузер на этой же машине
работают без пароля. Если `metrics-bind` смотрит в сеть, сервер **не
запустит** эндпоинт без токена и скажет об этом в лог:

```
ERROR metrics disabled: metrics-bind=0.0.0.0 is reachable from the network,
but metrics-token is empty; set one with `chunkwake config set metrics-token
<long random string>` or bind to 127.0.0.1
```

Задать токен (не короче 16 символов, без пробелов):

```properties
metrics-bind=0.0.0.0
metrics-token=длинная-случайная-строка
```

Вход:

- **браузер** — откройте `http://адрес:25585/?token=...` один раз: сервер
  поставит куку `cw_metrics` (HttpOnly, SameSite=Strict) и перекинет на `/`
  без токена в адресе. Без куки и токена страница покажет форму входа;
- **`chunkwake top`** — токен читается из того же `server.properties` и уходит
  заголовком `Authorization: Bearer`;
- **Prometheus** — тот же заголовок в `scrape_configs`.

Попутно закрыт DNS rebinding: если браузер прислал `Origin`, он должен
указывать на тот же хост, иначе ответ `403`. Это важно, потому что иначе
чужая страница могла бы дёрнуть локальный дашборд из браузера жертвы.

Токен сравнивается побайтово без раннего выхода, чтобы по задержке нельзя
было подбирать его посимвольно.

## Что меряется

**Тик.** Кольцевой буфер на 18 000 тиков (15 минут). Считаются TPS по окнам
1/5/15 минут, средний MSPT за минуту, перцентили p50/p95/p99, худший тик за
всё время и число опоздавших тиков (интервал больше целевого на 10 %).

**Процесс и машина.** Загрузка по каждому ядру, средняя по машине, доля
процесса в процентах одного ядра, RSS и виртуальная память, память системы.

**Мир.** Игроки, мобы, предметы, стрелы, сферы опыта, чанки в симуляции и
известные миру, очереди редстоуна/жидкостей/воронок, печи, костры, задачи
пула генерации.

**Сеть.** Байты и пакеты в обе стороны, средний и худший пинг по RTT
`keep_alive`.

## `/top`

```
/top            всё
/top tick       только тик
/top cpu        только процессор
/top mem        память
/top world      мир
/top net        сеть
```

Каждая строка — отдельный элемент компонента, подробности — в подсказке при
наведении, поэтому экран не забивается цифрами. Полоска `█░` показывает
загрузку: зелёная до 70 %, жёлтая до 90 %, красная выше.

Параметры:

| Флаг | Значение по умолчанию | Что делает |
|---|---|---|
| `--dir PATH` | текущий каталог | где взять `server.properties` с `metrics-*` |
| `--host HOST` | `metrics-bind` | адрес эндпоинта |
| `--port PORT` | `metrics-port` | порт эндпоинта |
| `--watch SEC` | — | перерисовывать каждые SEC секунд |
| `--json` | — | печатать снимок как JSON |
| `--no-color` | — | без ANSI-цветов (для логов) |

## Настройки

```properties
metrics-enabled=true
metrics-bind=127.0.0.1
metrics-port=25585
metrics-token=
```

По умолчанию эндпоинт слушает только loopback: метрики не должны уходить
наружу без явного решения. `metrics-token` нужен только при внешнем
`metrics-bind` — см. «Доступ к дашборду».

Страница отдаётся сжатой (`gzip`), если браузер это умеет: 80 КБ исходящих
превращаются в 24. Скрытая вкладка закрывает поток и не тянет кадры, а
видимые графики перерисовываются только при новых данных, движении курсора
или анимации входа — в покое вкладка не жжёт CPU.

Если `metrics-port` занят (например, остался прошлый сервер или рядом второй
экземпляр), сервер пробует следующие два порта — `25586`, `25587` — и пишет
в лог, на каком слушает:

```
WARN dashboard on http://127.0.0.1:25586/ (port 25585 is busy; `chunkwake top --port 25586` or update metrics-port)
```

`chunkwake top` перебирает те же три порта, поэтому без флагов находит сервер
и после сдвига.

## Профиль тика

`/debug start` (или `/perf start`) пишет в `debug/profile-<время>.txt` строки
`тик<TAB>MSPT`; `/debug stop` возвращает путь. Профиль ограничен пятью
минутами тиков, дальше запись прекращается.

Отдельно от этого файла сервер всегда, без всяких команд, снимает разбивку
тика по подсистемам — как `spark`, только без стеков:

| Где | Что видно |
|---|---|
| `GET /` → «На что уходит тик» | стековая диаграмма по секундам и список групп |
| `chunkwake top` | секция `PROFILE`: группы, `ms/тик` и доля |
| `GET /api/profile` | JSON: 900 секунд по `{ at, ticks, total[18], max[18] }` |

**По умолчанию — группы, а не фазы.** Внутренние названия («плиты»,
«правки плагинов», «рассылка блоков») читаются как отладка, а не как ответ
на вопрос «что тормозит тик», поэтому на странице семь понятных групп:

| Группа | Что внутри |
|---|---|
| Мобы и животные | ИИ, движение, спавн |
| Хопперы и механизмы | печи, костры, поршни, редстоун, жидкости, плиты |
| Предметы и снаряды | дроп на земле, стрелы, опыт |
| Отправка игрокам | пакеты о блоках и позициях |
| Чанки в симуляции | пересчёт чанков рядом с игроками |
| Плагины | код плагинов в тике |
| Служебное | часы мира и прочая мелочь |

Точные 18 фаз остаются под переключателем «Подробно» и в JSON — они нужны,
когда группу уже нашли и надо понять, что внутри неё. Время на странице
показывается в **мс на тик** (как бюджет), а не суммой за секунду: 10511 мс
за минуту ничего не говорит, а 8.75 мс из 50 — говорит.

Время снимается в `tick_once` секундомером: `lap` после каждой подсистемы
начисляет прошедшее ей. Замер — одно чтение `Instant` на фазу и два на тик
сверху, поэтому профиль работает всегда, а не только под `/debug start`:
именно так и ловят разовый всплеск, случившийся до того, как включили запись.

Фазы (порядок и ключи стабильны, на них опираются JSON и подписи):

```
refresh    чанки симуляции        deferred   правки плагинов
items      предметы               plates     нажимные плиты
arrows     стрелы                 fluids     жидкости
mobs       мобы                   pistons    поршни
animals    животные               hoppers    воронки
orbs       сферы опыта            scheduled  редстоун
furnaces   печи                   blocks     отправка блоков
campfires  костры                 moves      отправка позиций
                                  plugins    плагины
                                  time       часы мира
```

`/tick rate 0` и заморозка сюда не входят: тик не идёт — профиль стоит.
На пустом сервере почти всё время лежит в `time`: подсистемы не запускались,
и часы мира — единственная работа тика. Поэтому пустая панель показывает
«Служебное» и почти ноль, а не набор строк с прочерками.

Чего здесь нет, в отличие от `spark`: стеков вызовов, конкретных блоков и
чанков. Разбивка по подсистемам отвечает на вопрос «куда уходит время тика»,
а не «какой именно моб тормозит». Разбор внутри подсистемы — по-прежнему
`/debug start` плюс профиль-файл.
