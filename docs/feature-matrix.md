# Фич-матрица

Очередь **M7**: генерация мира, редстоун и остальная ванила. Внутри раздела сверху вниз. Строки со статусом «готово» — граница, их в работу не берут. M7 берёт «нет» и «частично».

Протокол, чанки, Anvil, игрок, инвентарь, крафт 2×2 и верстак, печи (`smelting`, `blasting`, `smoking`), чары, жидкости, лук и арбалет, стрелы и сферы опыта описаны в [milestones.md](milestones.md) и сюда построчно не копируются. Здесь только дыры внутри этих областей и то, чего там нет. M6 и M8 в эту матрицу не входят.

Память сервера: `memory-profile=auto|low|normal` выбирает потоки и лимиты
кэшей; `low` проверен на полёте 20 блоков/с с обзором 10 (средний обзор
99.2 %). Индексы секций до 16 состояний занимают 2 КиБ, неизменяемые таблицы
состояний генератора разделяются между измерениями, кэши чистятся при
простое. Замеры — в [perf.md](perf.md). Метки декорации и наборы сущностей
пока не ограничены: они сохраняют однократность генерации и заселения.

Статусы:

- **готово** — заявленное поведение уже играет.
- **частично** — игрок уже может этим пользоваться; в заметке сказано, чего нет.
- **нет** — имени блока в `is_source`, чтения свойства `power`, коллизии поршня или звука установки недостаточно. Это заготовка данных, не механика.

Строка — семейство механик, не вид дерева и не вид моба.

## Генерация и измерения

Плоский мир собирается `ChunkColumn::flat`. `level-type=minecraft:normal` заполняет недостающий чанк шумом оверворлда (камень, воздух, вода, лава), расставляет биомы по климату и наносит поверхностный слой (трава, земля, песок, снег, deepslate, руды меди и железа). `large_biomes` и `amplified` берут свои `noise_settings`, `single_biome_surface` держит один биом, плоский `the_void` с фичами ставит стартовую платформу. Карверы вырезают пещеры и каньоны, фичи расставляют руды, деревья и растительность. Колодец, окаменелости и серный источник ставятся из `.nbt`. Деревни, пиллагерские аванпосты и брошенные лагеря собираются из пулов. Пустынная пирамида и храм в джунглях — один кусок. Шахт нет.

Дерево кусков сходится с `server.jar` бит в бит: все 274 куска на сиде 12345 совпадают по порядку, коробке и повороту (тест `trial_matches_vanilla_pieces`). ## Плагины (Paper API)

`paper-api.jar` целиком лежит в classpath JVM: классы не переписаны и не сгенерированы, реализуется только поведение. Недостающий метод сервера возвращает пустое значение и **один раз** пишется в журнал как `api: <интерфейс>.<метод> is not implemented` — список того, что стоит закрыть, виден без отладки. Строгий режим (исключение вместо пустого значения) — `CHUNKWAKE_API_STRICT=1`.

| Фича | Статус | Заметка |
|---|---|---|
| API встроен в бинарь | готово | `java/dist` (48 jar'ов, `crates/bridge/build.rs`) упаковывается в zip, встраивается в exe и разворачивается в `<каталог сервера>/api` при первом старте: релиз — **один файл**, рядом ничего раскладывать не нужно. Отпечаток архива в `.chunkwake-api-bundle`: после пересборки API заменяется, до тех пор второй запуск ничего не пишет. Сборка без встраивания — `CHUNKWAKE_API_BUNDLE=none`. Проверено на чистом каталоге: только `chunkwake.exe` + плагин → `enabled 1 plugin(s)`, `doctor` — `Ready to start` |
| Библиотеки из `plugin.yml` | готово | Секция `libraries:` резолвится `MavenLibraryResolver` из paper-api и попадает в classpath плагина до создания main-класса; скачанное кэшируется в `libraries/` рядом с сервером. Без этого BlueMap не стартовал: `com.flowpowered:flow-math` (см. `Libraries.java`) |
| Сервисы paper-api (`ServiceLoader`) | готово | 12 провайдеров: 5 своих (`InternalAPIBridge`, `ServerBuildInfo`, `RegistryAccess`, `PluginLoader`, `LifecycleEventTypeProvider`) и 7 сгенерированных задачей `:api-impl:generateProviders` из `java/tools/GenProviders.java`. 8 из них объявлены package-private — реализовать их можно только классом в пакете paper-api, поэтому руками не пишутся: генератор читает paper-api.jar и выдаёт `Chunkwake<Имя>` плюс `META-INF/services`. При смене версии paper-api всё перегенерируется |
| События жизненного цикла | частично | `LifecycleEvents.COMMANDS` диспетчеризуется сразу при подписке: команды плагина попадают в `CommandMap` и играются (`/bluemap` виден в игре). `DATAPACK_DISCOVERY` отдаёт `DatapackRegistrar`: из пака плагина (каталог или ресурс jar) читаются только теги блоков и предметов. Теговые события (`TAGS`) регистрируются, но не наступают |
| `paper-plugin.yml`: `loader` и `bootstrapper` | готово | `PluginLoader.classloader` — библиотеки из Maven (`MavenLibraryResolver`) и `ClassPathLibrary` до создания плагина; `PluginBootstrap.bootstrap(BootstrapContext)` и `createPlugin`. Без этого Veinminer падал на `KPaper` |
| Зависимости между плагинами | готово | Порядок загрузки и включения — по `depend`/`softdepend`/`loadbefore` (`PluginOrder`), `provides` засчитывается; без обязательной зависимости плагин не грузится, как в Paper. Классы общие (`PluginClassGroup`, глобальная группа Paper для `plugin.yml`): чего нет у родителя и в своём jar, ищется у других плагинов — сначала у зависимостей; доступ к плагину не из зависимостей пишется в журнал. Загрузчики параллельные: взаимные ссылки из разных потоков не встают |
| Команды Paper | готово | Как в Paper 26.3 (вывод сверен с байткодом `PaperPluginsCommand`/`PaperVersionCommand`/`PaperMSPTCommand`): `/plugins` (`/pl`, секции Paper/Bukkit, зелёный — включён, красный — выключен, `*` — legacy, клик → `/version`), `/version` (`/ver`, `/about`, с плагином — версия, сайт, авторы; поиск по части имени), `/mspt` (avg/min/max за 5 с, 10 с, 1 мин), `/help` (темы по всем командам, алиасы, индекс по плагину), `/bukkit:reload [confirm]` (выключает плагины, закрывает загрузчики и грузит каталог заново; отказ, если плагин зарегистрировал lifecycle-обработчик, — как Paper). Права `bukkit.command.*` с default Bukkit, `ServerLoadEvent` STARTUP/RELOAD. Команда плагина перекрывает ванильную с тем же именем, ванильная доступна как `minecraft:<имя>`. Дерево у клиента — по default права команды (оператор/все/не-операторы); права, выданные плагином (LuckPerms), дерево пока не учитывает. `Server.getTPS`/`getAverageTickTime` — из окна тиков Rust |
| Реестры Bukkit/Paper | готово | Все 44 `RegistryKey` paper-api заполнены ванильными ключами. Rust отдаёт их кусками по запросу `registry <имя> <с какой>`: встроенные реестры — по ID из `registries.json`, data-driven — в сетевом порядке, `worldgen/structure` — из файлов данных. Значение строится по типу (`RegistryValues`). Интерфейсы (`Attribute`, `Sound`, `Biome`, варианты мобов…) — прокси с `name()`/`ordinal()` как у Paper `OldEnumHolderable` и ванильным ключом перевода. Enum (`EntityType`, `Particle`, `PotionType`) — их константы. Для абстрактных классов — свои подклассы: `GameEvent` (радиус 16/10/32, частота вибрации по `VibrationSystem`), `Structure` (тип из файла), `StructureType`, `MusicInstrument` (звук, длительность, дальность), `GameRule` (тип и умолчание из таблицы `/gamerule`; `legacyGameRuleBridge` для старых констант). `Attribute.getDefaultValue` — ванильная база, `getSentiment` — по `Attributes`. `BlockType` и `ItemType` отдаются как `Typed`, `Biome.CUSTOM` — как у Paper. `World.getGameRuleValue`/`setGameRule`/`getGameRules` читают и пишут те же правила, что `/gamerule`. Тест `RegistriesTest`: на ванильных данных инициализируются все классы-держатели констант, ни одна константа не `null`. Живой прогон: Veinminer получает `BlockBreakEvent` без падения на `Attribute`. Не сделано: данные записей помимо ключей (цвета вариантов, свойства биомов и т. п. — мягкие умолчания) |
| Атрибуты сущностей для плагинов | готово | `Player.getAttribute` и `getAttribute` мобов отдают `AttributeInstance` поверх запроса `attr <uuid> <атрибут> get|base|reset|add|remove`. База, модификаторы и пределы — те же, что у `/attribute`: видны модификаторы эффектов, чар, команд и плагинов, итог считается по ванильной формуле, клиент получает `update_attributes`. Атрибута нет у сущности — `null`, как у ванилы. Повторный `addModifier` с тем же ключом — `IllegalArgumentException`, как у Paper. Тест `AttributeInstanceTest`. Живой прогон: Veinminer при ломании блока снимает свой модификатор без ошибок. Не сделано: временные модификаторы хранятся как обычные, сохранения атрибутов между входами нет |
| Планировщики Folia | готово | `getGlobalRegionScheduler`, `getRegionScheduler`, `getAsyncScheduler` и `Entity.getScheduler` ведут себя как у Paper на обычном сервере (`FoliaGlobalRegionScheduler`, `FallbackRegionScheduler`, `FoliaAsyncScheduler`, `FoliaEntityScheduler`): те же проверки задержек и периода, `IllegalPluginAccessException` для выключенного плагина, машина состояний `ScheduledTask` (`cancel` изнутри повторяющейся задачи — `NEXT_RUNS_CANCELLED`). Регион один — главный тик плагинов; тиковые задачи Folia не видны через `BukkitScheduler`. Асинхронные — таймер плюс виртуальные потоки. Задачи сущности после её исчезновения не выполняются, вместо них один раз вызывается `retired`. `isOwnedByCurrentRegion`/`isGlobalTickThread` — `true` на главном потоке плагинов. При выключении плагина его задачи отменяются. Тест `FoliaSchedulersTest`. Живой прогон: тестовый плагин с `folia-supported: true` — все четыре планировщика выполнили задачи. Не сделано: настоящей многопоточности регионов нет |
| Реестры ванили в JVM (NMS) | частично | Классы `net.minecraft.*` из `server.jar` (`api/game-classes.jar` и `game-libs`) лежат в classpath JVM плагинов. Ванильный `Bootstrap.bootStrap()` (`VanillaBootstrap`) идёт в своём потоке сразу после старта JVM, параллельно с Via; загрузка плагинов ждёт его, как на Paper. Подменённые бутстрапом `System.out`/`err` возвращаются обратно. Занимает около 2,7 с и 80 МБ кучи; без jar игры пропускается. Живой прогон: commonnetworking включается без «Not bootstrapped». Не сделано: `MinecraftServer.getServer()` (Veinminer), `CraftServer.getServer` (voicechat) — ванильного сервера в JVM нет; нужны шимы |
| Теги для плагинов | готово | `Server.getTag` для `blocks`/`items` (`Material`): ванильные теги из Rust (`tag block|item имя` в `world_request`, вложенные раскрыты) плюс теги датапаков плагинов; файл без `replace` дополняет тег, как в ванили. Veinminer принимает `#c:ores` и `#minecraft:pickaxes`. Нет `getTags` и тегов других реестров |
| Каналы плагинов | готово | `Messenger` — `StandardMessenger` из Bukkit. `custom_payload` от клиента идёт событием в мост: `minecraft:register`/`unregister` (и из configuration, после входа) — каналы игрока и `PlayerRegisterChannelEvent`, остальное — `dispatchIncomingMessage`. `Player.sendPluginMessage`/`Server.sendPluginMessage` шлют `custom_payload`, только если клиент объявил канал (как `CraftPlayer`); после `PlayerJoinEvent` клиенту уходит `minecraft:register` с входящими каналами. Проверено ботом `payload_probe` и плагином-эхо. Также `getServicesManager` (`SimpleServicesManager`, снятие при выключении плагина), `isStopping`, `getUnsafe` (только `getProtocolVersion` 777 и `getDataVersion` 5023) |
| События входа, кика, телепорта и ввода | готово | Порядок Paper после авторизации: `AsyncPlayerPreLoginEvent` (и устаревший `PlayerPreLoginEvent` при слушателях) в своём потоке `User Authenticator #N` с `PlayerProfile` (свойства session server) и `PlayerLoginConnection`; затем проверки ванили `canPlayerLogin` (бан IP и игрока, белый список, места — без обхода для операторов) и `PlayerConnectionValidateLoginEvent` с их причиной, поверх — `PlayerLoginEvent` (как `HorriblePlayerLoginEventHack`); игрок события уходит в `PlayerJoinEvent`. `PlayerKickEvent` от `/kick` (`multiplayer.disconnect.kicked`), `/ban` (`BANNED`), `/ban-ip` (`IP_BANNED`) и `Player.kick`: отмена, своя причина, сообщение о выходе и `QuitReason.KICKED`; причина доходит клиенту пакетом `disconnect`. `PlayerRespawnEvent` (`DEATH`, `END_PORTAL`, кровать/якорь, смена точки), `PlayerTeleportEvent` от `/tp` (`COMMAND`) и жемчуга (`ENDER_PEARL`, отмена — без урона), `PlayerItemHeldEvent` (отмена возвращает слот), `PlayerToggleSneakEvent`, `PlayerToggleSprintEvent`. Также `getPlayerProfile`, `getAddress`, `Server.createProfile`. Тест `LoginEventsTest`; живой прогон тестовым плагином и `opcmd_probe` (`INPUTS=1`, `RESPAWN=1`) — все события пришли. Не сделано: `hostname` из handshake пуст, `InventoryOpenEvent` для ванильных контейнеров |
| Клиенты других версий (ViaVersion) | частично | jar-ы ViaVersion, ViaBackwards, ViaRewind из `plugins/` поднимаются библиотекой (`ViaLoader`, своя платформа в `java/dist/via/chunkwake-via.jar`), а не Bukkit-плагином: их Bukkit-платформа внедряется в Netty Java-сервера. Клиент «чужой» версии получает сессию перевода (`Translator` в `chunkwake_net`): каждый пакет после распаковки идёт через `UserConnection` на `EmbeddedChannel` в JVM, клиенты 26.3 идут мимо. Статус отвечает каждой версии её протоколом (`via_probe`: 1.7–26.3). Клиенту без пака `minecraft:core:26.3` реестры уходят с данными записей из JSON датапака, как у ванилы. Бот 1.21.1 (`via_login_probe`) проходит вход, configuration и play (чанки, сущности, keep-alive). Клиенты до 1.8 входят без сжатия. В `PluginManager` стоят плагины Via с их версиями, `/viaversion` работает, классы Via видны плагинам (`Via.getAPI()`), `Player.getProtocolVersion` — версия клиента. Не проверено живыми клиентами старых версий; Via-кик закрывает соединение без пакета disconnect |
| `World.save()` | готово | Просит сервер записать мир на диск; `/save-all` идёт тем же путём (`take_save_request` в автосейве). BlueMap зовёт это при включении |
| Каталог мира плагинам | готово | `Server.getLevelDirectory()` и `getWorldContainer()` отдают настоящий каталог мира (абсолютный путь), `World.getWorldPath()` — каталог измерения, как `CraftWorld`: `dimensions/<ns>/<путь>`. | Миры, Metadatable и PDC | частично | `getWorlds()` — оверворлд, Незер и Энд под именами Paper (`world`, `world_nether`, `world_the_end`) с ключами, окружением, высотами; `getWorld` по имени, UUID и ключу.
