# Критерии оценки

Оформить как таблицу в `docs/criteria.md`, каждому критерию — метрика и способ замера, сравнение с Paper/Folia/Purpur/Leaf на одинаковом стенде.

1. **Производительность тика:** MSPT p50/p99 при N игроков (100/500/1000), TPS под нагрузкой, масштабирование по ядрам (Paper ≈ 1 основной поток; Folia масштабируется, но ломает плагины).
2. **Плотные сценарии:** все игроки в одной точке (слабость Folia — один регион = один поток), фермы мобов, редстоун-машины, массовые TNT/жидкости.
3. **Память:** RSS на игрока/на загруженный чанк, отсутствие GC-пауз в движке (у Java-ядер — паузы G1/ZGC).
4. **Сеть:** пропускная способность, задержка, CPU на шифрование/сжатие, анти-DoS (лимиты пакетов, handshake flood).
5. **Чанки и I/O:** скорость генерации и загрузки (чанков/с), время сохранения мира без лагов, время старта сервера.
6. **Совместимость плагинов:** % проходящих тестов на топ-50 плагинов с SpigotMC/Hangar/Modrinth; % покрытия Bukkit/Paper/Purpur API (автоподсчёт по сигнатурам); работа не-Folia плагинов (Folia: 0%).
7. **Ванильная корректность:** паритет механик (редстоун, техничные фермы, дюпы/баги, которые сообщество хочет сохранить — опции как в Purpur/Leaf), прохождение тест-миров.
8. **Конфигурируемость:** покрытие опций Purpur/Paper/Leaf, горячая перезагрузка конфигов.
9. **Наблюдаемость:** встроенный профайлер (аналог spark), метрики Prometheus, timings по регионам и по плагинам.
10. **Безопасность и стабильность:** изоляция падения плагина, watchdog, отсутствие data race (Rust гарантирует для движка; на мосту — проверяемые handle'ы).
11. **Операционные:** размер бинаря, старт, кроссплатформенность, обновления.
12. **Developer experience:** документация, расширенный API (async-события, нативные Rust-плагины в будущем), скорость сборки.

Известные пробелы конкурентов как ориентиры: Paper — однопоточный главный тик; Folia — несовместимость с большинством плагинов, проблемы плотных регионов; Purpur/Leaf — форки поверх Paper/Gale, наследуют модель потоков, Leaf частично асинхронизирует (async pathfinding, entity tracker), но с риском для плагинов; Bukkit/Spigot — устаревающий API, медленный.
