# Участие в Chunkwake

Спасибо, что хотите помочь. Цель проекта — сервер Minecraft 26.3, который ведёт
себя 1 в 1 как ванильный `server.jar` и запускает плагины Paper и Folia без
переделок. Отсюда почти все правила ниже.

## С чего начать

- Строки «частично» и «нет» в [фич-матрице](docs/feature-matrix.md) — готовый
  список задач.
- Issue с меткой `vanilla-parity` — найденные отличия от ванили, у них уже
  есть шаги воспроизведения.
- Перед большой работой откройте issue или напишите в существующем: так две
  реализации одной механики не появятся параллельно.

## Сборка и проверки

Нужны stable Rust и Java 25 (для данных из `server.jar` и для моста плагинов).
Подробно — в [docs/running.md](docs/running.md).

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Если менялся мост плагинов (`java/` или `crates/bridge`):

```bash
cd java && ./gradlew :api-impl:test
```

Сверки с ванилью в тестах включаются переменной `CHUNKWAKE_DATA` — путь к
дереву `generated/26.3`, которое `build.rs` собирает из `server.jar`.

## Правила

- **Сначала ваниль.** Прочитайте нужный класс `server.jar` или Paper (`javap`,
  декомпилятор), а не угадывайте поведение. В PR напишите, с чем сверялись.
- **Тест на поведение.** Юнит-тест, сверка с ванильными данными или проба ботом
  из `crates/bots/examples` против настоящего `server.jar`.
- **Плагинное событие вместе с механикой.** Если у механики есть событие Paper,
  оно должно стрелять в том же месте, в том же порядке и с той же отменой.
- **Генерация мира не меняется молча.** Хэш сгенерированного мира должен остаться
  прежним; если он меняется намеренно — объясните почему.
- **Матрица честная.** Сделали механику — обновите строку в
  [feature-matrix.md](docs/feature-matrix.md), включая то, чего ещё нет.
- **Скорость — вторая цель.** Оптимизация не должна менять поведение; цифры
  «до/после» — в [docs/perf.md](docs/perf.md).
- Комментарии, документация и сообщения коммитов — на русском.

## Pull request'ы

На каждый PR запускается [pr.yml](.github/workflows/pr.yml):

| Проверка | Когда |
|---|---|
| `cargo fmt --check` | всегда |
| clippy и тесты на Linux | если менялся Rust |
| JUnit моста | если менялась Java-часть или `crates/bridge` |

Полный CI — две ОС и релизные бинарники со встроенным API — идёт после слияния,
на push в ветку версии. Теги в сообщении коммита:

| Тег | Что делает |
|---|---|
| `[skip tests]` | не гонять clippy и тесты (fmt в PR остаётся) |
| `[skip release]` | не собирать релиз (только на push) |
| `[skip both]` | ни то, ни другое |
| `[skip ci]` | не запускать ничего |

## Сообщить о проблеме

Шаблоны issue подскажут, что нужно: отличие от ванили, несовместимый плагин,
ошибка или предложение. Уязвимости — только приватно, см. [SECURITY.md](SECURITY.md).
